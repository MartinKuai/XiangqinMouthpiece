# Portfolio Package - 相亲嘴替

> 作品集包装文档，可直接用于作品集说明和面试讲解。

---

## 一句话介绍

**相亲嘴替** — 输入相亲对象的离谱发言，AI替你体面发疯。

## 项目背景

### 业务/用户痛点

相亲场景中经常遇到各种尴尬发言：
- 查户口式提问："你工资多少？""你有房吗？"
- 普信发言："我这个人比较直"
- 油腻暧昧："刚拍的，帅吗？"
- 价值观冲突："女生太强势不好"

用户需要一个工具，帮助生成既不失礼貌又有边界的回复。

### 解决方案

构建一个AI驱动的"嘴替"工具：
- 输入一句离谱发言
- AI生成4种风格的回复
- 覆盖从"真发"到"整活"的不同场景

## AI Workflow

### 1. 用户输入层

- 文本输入 + 场景标签 + 视角选择 + 强度选择
- 前端校验（长度、空值）
- 可选访问码控制

### 2. Serverless 代理层

- Netlify Functions 接收请求
- 环境变量读取 API Key
- 输入校验和安全检查
- 调用 DeepSeek API

### 3. AI 生成层

- 系统 Prompt 约束风格
- 结构化 JSON 输出
- 安全边界控制
- 降级处理机制

### 4. 输出展示层

- 4张回复卡片
- 不同风险等级标注
- 一键复制功能
- 移动端适配

## Prompt 约束设计

### 风格约束

```
低门槛、短反转、轻冒犯、别装
- 表面平静，实际反客为主
- 不脏不骂，有点损
- 1秒内能看懂笑点
```

### 安全边界

```
禁止：
- 人身攻击
- 脏话
- 性别对立
- PUA/情绪操控
- 性羞辱/外貌羞辱

降级处理：
- 检测到辱骂/仇恨/暴力内容
- 返回安全回应
- 不升级冲突
```

### 输出约束

```json
{
  "cards": [
    { "type": "真发版", "riskLevel": "适合真发" },
    { "type": "阴阳版", "riskLevel": "看关系" },
    { "type": "日常脑回路错位版", "riskLevel": "看关系" },
    { "type": "抽象整活版", "riskLevel": "仅供整活" }
  ]
}
```

## 内容安全机制

### 1. 输入层安全

- 长度限制（120字）
- 空值校验
- 访问码控制

### 2. Prompt 层安全

- 明确禁止清单
- 降级处理指令
- 风格边界约束

### 3. 输出层安全

- JSON 结构化输出
- 风险等级标注
- 免责声明

### 4. 展示层安全

- "仅供整活"标签
- 页面免责声明
- 不鼓励真实发送

## 面试讲解话术

### 开场

"相亲嘴替是一个AI驱动的整活工具，用户输入相亲对象的离谱发言，AI会生成4种不同风格的回复，从适合真发的温和版到仅供娱乐的抽象版。"

### 技术亮点

"技术上有几个亮点：

1. **Prompt Engineering**：通过结构化约束，让AI输出严格的JSON格式，同时控制风格边界。

2. **内容安全**：设计了多层安全机制，包括输入校验、Prompt约束、输出标注，确保不会生成人身攻击或性别对立内容。

3. **Serverless架构**：使用Netlify Functions做API代理，既保护了API Key，又实现了零运维部署。

4. **用户体验**：做了很多细节，比如按钮冷却防重复点击、输入长度限制、一键复制、风险等级标注。"

### 产品思考

"产品上，我刻意保持了'轻工具'的定位：
- 不做用户系统，降低使用门槛
- 不做内容库，保持AI生成的新鲜感
- 可选访问码，灵活控制访问范围
- 明确的免责声明，界定工具边界"

### 遇到的挑战

"最大的挑战是**内容安全**。既要让回复有'锋芒'，又不能变成人身攻击。我通过：
- 明确的禁止清单
- 风险等级标注
- 降级处理机制
来平衡这个矛盾。"

### 总结

"这个项目展示了从产品设计到技术实现的完整能力，特别是AI产品的安全边界设计，这在实际工作中非常重要。"
